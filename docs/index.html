What works today

Manifest validation and configuration export for Claude Code, VS Code, Cursor, and OpenCode, plus an optional local AI profile (Ollama by default) with a health check. Live assistant connections and local models still need setup and testing. This prototype is not a hosted gateway, marketplace, or universal compatibility layer.

A small workshop you can carry.

Ian’s working belt brings API development, data pipelines, and browser QA into one reviewable project. Start from it—or begin with an empty belt and make it yours.

Make it yours

An empty belt.
A useful first prompt.

The template branch is the blank starting point. It leaves out Ian’s personal connections and skills so you can add only what you need.

  1. Copy the template branch.

    Clone the branch below. Create your own empty GitHub repository and replace the remote before pushing.

  2. Describe your workflow.

    Ask your coding assistant to read AGENTS.md and the README, then help you add your first connection, skill, and rules.

  3. Validate, export, and review.

    Generate a fresh client configuration, inspect it, and follow the client’s own trust and authentication flow.

Browse the blank template ↗
Terminal / Python 3.10+
# Start from the blank branch
git clone --branch template --single-branch \
  https://github.com/ianmkinney/Ian-tool-belt.git \
  my-tool-belt
cd my-tool-belt

# Check and generate configuration
python3 scripts/validate.py belt.json
python3 scripts/export.py belt.json \
  --target claude-code --out dist/claude-code

# Or export for VS Code
python3 scripts/export.py belt.json \
  --target vscode --out dist/vscode
TRY THIS PROMPT

“Read AGENTS.md and README.md. Help me build my belt for my projects. Start with one useful MCP connection and one original skill. Keep credentials out of Git, test changes, and explain anything my assistant doesn’t support.”

Exports require a new output directory and do not overwrite your assistant’s existing configuration.

Portable, with honest boundaries

One source. Explicit adapters.

The exporter translates connection settings and packages rules and skills. You still configure each client, provide credentials, and explicitly load the instructions.

ClientCurrent outputStatus
Claude Code.mcp.json + instruction filesExport supported; live setup untested
VS Code.vscode/mcp.json + instruction filesExport supported; live setup untested
Cursor.cursor/mcp.json, rules, and skillsExport supported; live setup untested
OpenCodeopencode.json + skills + local modelExport supported; live setup untested
ChatGPTNo adapter yetNot supported by the exporter

Successful export does not mean a service is connected. Rules do not override host policies, and CI monitoring does not continue after an active session ends. Read setup and compatibility ↗
